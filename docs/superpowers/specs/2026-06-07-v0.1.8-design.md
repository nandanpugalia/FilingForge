# FilingForge v0.1.8 — Design Spec (council-revised)

**Date:** 2026-06-07
**Status:** Approved for implementation (revised after 3-idiots spec audit)
**Theme:** Premium-grade reports everywhere + monetization on + release discipline

## Release plan (revised — fixes the beta-gate bootstrapping paradox)

The beta-gate can't protect stable users from the very release that *introduces* it (they don't
have the gate yet). So C ships **first, alone, to stable**, then gates the big release:

- **v0.1.7.1** = **C only** (beta-gate toggle + updater endpoint switching). Ships straight to
  stable. Tiny, low-risk.
- **v0.1.8** = **A + B**, shipped **through** the beta gate (tag → beta feed → NP QAs the signed
  build → promote to stable). Build order within v0.1.8: **A → B** (B's paid skill reuses A's
  report helper). **Circuit breaker:** if B isn't green within ~2 weeks of A being green, ship
  v0.1.8 = A only; B becomes v0.1.9.

Each unit is built + tested as an isolated, independently-green unit.

Pre-traction, solo founder, no users yet (warming an X audience). Invariants held throughout:
the app sends **no usage telemetry**; an installed skill **runs fully offline forever** (the
Worker is touched only at purchase / redeem / update-check, never at run time).

## v0.1.7.1 — C: Beta-feed release gate

**Why:** today a tag auto-promotes live to everyone with no QA hold (v0.1.7 went straight live).

**Behaviour:**
- New Setting **"Get pre-release updates"** (default **OFF**). NP turns it ON to be the beta tester.
- Tagged release → **beta feed** first; stable users unaffected until a manual **promote**.
- Updater checks **beta** feed when toggle ON, **stable** when OFF.

**Mechanism (council-resolved):**
- **Stable feed:** GitHub's `releases/latest/download/latest.json` — it ignores prereleases, so
  stable stays put while a beta is out. **Promote = un-mark the release as prerelease** (it
  becomes the newest non-prerelease → stable endpoint serves it). Reliable, no JSON editing.
- **Beta feed:** publish `latest-beta.json` to **GitHub Pages** (`https://nandanpugalia.github.io/
  FilingForge/latest-beta.json`) — a fixed URL, simple CI step, avoids flaky release-asset
  overwrite patterns. CI adds a step on tag that generates + pushes it to `gh-pages`.
- **Runtime endpoint switch:** Tauri v2 reads `endpoints` at build-time, so switching needs custom
  Rust — call the updater with the URL chosen from the toggle. **De-risk first with a ~20-line
  spike** that reads the toggle and resolves/downloads from the matching endpoint before building C.

**Tests:** updater endpoint selection by toggle (unit/spike); manual: tag → only beta apps update
→ promote → stable apps update.

## v0.1.8 / A — Premium report everywhere (served reports + report-v2)

### A1 — Served reports (Safari citation fix) — with auth token (council security fix)
- The FastAPI sidecar serves the library root over http, via a route **path-restricted to the
  configured library dir** (`Path.resolve()` + `is_relative_to(root)`; reject `..`).
- **Per-session auth token (required).** On startup the app generates a random 256-bit token,
  passes it to the sidecar; the serve route **rejects any request without `?token=<value>`**. The
  app embeds the token in the "Open report" URL. Closes the "any local process / browser tab can
  read the financial library over loopback" hole.
- Also: **no directory listing** (404 on paths ending `/`), **reject symlinks** (or verify target
  is inside root), **deny CORS** (no CORS headers).
- **Dynamic port:** sidecar tries 8765, falls back to 8766–8775 if taken, writes the chosen port
  where the UI reads it. (Existing latent issue; the serve route makes it matter.)
- App **detects** reports by scanning each company's `research_report/` folder → Library view shows
  **"Open report"** → before opening, **ping `/health`** (toast "Starting engine…" + retry up to
  ~10s if the sidecar isn't up) → open `http://127.0.0.1:<port>/<lib-path>/research_report/
  business_model.html?token=…` in the **default browser**. http (not file://) makes citations
  open in **every browser, Safari included**.

### A2 — Report-v2 folded into the helper (keep the chart, graceful degrade)
- Replace `engine/report_helper.py` `_TEMPLATE` with Direction-C v2: dark masthead, **provenance
  header**, one-line thesis, numbered key findings, **fact-vs-analysis** separation, sticky context
  bar, collapsible sections, reading-progress bar, **Safari-safe citation handler** (preventDefault
  → try new tab → fall back to same-tab; never let a dead window swallow the click), and the inline
  **SVG narrative chart** (revenue bars + EBITDA-margin line from `data-*`, no libraries).
- **Chart kept, with graceful degradation:** the skill instructs the AI to populate the chart's
  `data-rev` / `data-margin` arrays from the filings; **if clean data isn't available, the chart is
  omitted entirely** (never a broken/empty box) — the rest of the report stands. The Safari handler,
  provenance, masthead and findings always render (no data dependency).
- Port `design-mockups/report-v2-direction-c.html` (gitignored) into the helper, parameterised.
- Update the Business Model Brief skill to fill provenance + chart data, degrading gracefully.

**Tests:** helper contains v2 markers (chart, provenance, fact/analysis, Safari handler) — extend
`test_report_helper.py`; serve route: rejects no-token, rejects traversal, rejects symlink, serves
in-library file with token (api tests); UI shows "Open report" when a report exists.

## v0.1.8 / B — Monetization: system-browser + deep-link paywall (council redesign)

### B1 — The purchase flow (system browser + deep link — NOT a webview)
1. Premium skill shows **"Get ₹3,000"**. (Button disabled immediately on click → re-enabled on
   return/error, so no double-open / double-charge.)
2. Click → app opens the Instamojo checkout in the **system default browser** (full native UPI/
   card/3DS — works everywhere).
3. Instamojo success **redirects to a custom deep link** the app registers:
   `filingforge://redeem?code=<redeem_code>`. The OS focuses FilingForge and hands it the link.
4. App parses the code → calls Worker `/redeem` → writes the watermarked `.md` into
   `~/.filingforge/skills/` → toast **"Concall Decoder added ✓ — Use it now."**
- **Optional stretch (only if a 1-hour ₹1 test proves it renders on macOS + Windows):** an
  in-app webview as a nicer-feeling variant, falling back to system-browser. Not a dependency.

### B2 — The server (Cloudflare Worker + KV, free tier)
- `POST /webhook/instamojo` — verify the **MAC signature** with Instamojo's exact algorithm
  (`sha1(sorted-concat-fields | salt)`; salt as a Worker secret; dedicated test with a known
  payload). **Idempotent + replay-safe:** write the purchase only if the key doesn't exist; keep
  `activations` in a separate key so a replay can't reset it. Record `{redeem_code (UUID), skill_id,
  version, email, name, phone, purchase_id, paid_at, activations:0, status:"paid"}`.
- `POST /redeem` — body `{code}`:
  - If the code isn't in KV yet (webhook race) → return **`202 {status:"pending", retry_in:3}`**;
    optionally the Worker verifies via Instamojo's **Payment Details API** on cache-miss.
  - If found + valid → enforce **activation cap (5)**, inject **email watermark**, return the
    **current version** of the `.md`.
  - **Rate-limit** (≈5/min per IP); **identical error messages** for not-found / expired / capped
    (no enumeration); log attempts. Reject **refunded** codes.
- `GET /skills-manifest` — latest version per skill (for the deferred in-app update check).
- **Redeem code is a generated UUID**, never the Instamojo `payment_id` (which is guessable).
- Refund: handle Instamojo's `Refunded` webhook → mark `status:"refunded"` → `/redeem` rejects it.
- **Admin:** `POST /admin/reset-activations {code}` (secret-protected) + a `wrangler kv put` runbook
  so NP can manually insert a purchase if a webhook is ever lost. Document in `RELEASE_QA.md`.

### B3 — Fail-safes (a payment never strands a buyer)
- **Three delivery paths:** (1) deep-link auto-install (primary); (2) **"Redeem code"** field —
  paste the code from Instamojo's email; (3) existing **"Import a skill"** picker. **No drag-drop.**
- **Polling belt:** after opening checkout, the app may also poll `/redeem?code=<pending>` so even
  if the deep link is missed, a completed payment still installs. (Combine fast deep-link + reliable
  poll.)
- **Re-fetchable** purchase up to the activation cap → reinstall / new machine recovers.
- **Offline / Worker down at redeem** → "Your purchase is safe — your code's in your email; we'll
  install when you reconnect." Payment is recorded at Instamojo + KV; delivery retries forever.
- **Email delivery (Instamojo auto-deliver):** the `.md` (generic, owner's copy + ultimate
  fallback) + a `HOW-TO.md` + receipt + redeem code. **Acknowledged:** the emailed `.md` is
  **un-watermarked** (Instamojo sends a static file); the watermark applies only to the app/Worker
  copy → it's a soft deterrent, not a lock. Accepted (zero-friction delivery > watermark purity).

### B4 — Skill updates ("includes updates")
- **Launch (free, deliverable):** each `.md` carries a version; the Worker serves latest for a valid
  code; NP emails the customer list the new file when an update ships. No re-payment ever.
- **Deferred (build when first update ships):** `/skills-manifest` + app daily-check → "Update
  available" badge → one-click re-redeem. (Availability check folded into the existing daily ping;
  not usage telemetry.)

### B5 — In-app store affordance
- Premium skills show **"Get ₹<price>"** (→ B1) instead of "Use"; a small **"Redeem code"** entry;
  owned premium skills behave like any imported skill ("Use").

### B6 — Customer data + policies
- **Instamojo handles** payment + all card/UPI credentials (we never see them) + the receipt email.
- **We receive** (webhook + dashboard): name, email, phone, amount, product, purchase_id, timestamp
  = the customer list (updates, support, watermark). Purchase data, not app telemetry.
- **Policies (drafted):** Refund ("all sales final — digital goods, instant delivery, no refunds;
  contact support if it won't install"), License ("personal-use license, don't redistribute/resell;
  updates included"), Privacy ("name+email for purchase + updates; Instamojo processes payment; app
  sends no usage data"). Placed: Instamojo product page + account policy fields + website
  `/refunds` `/privacy` `/terms` + the delivery email.

### Division of labour (B)
- **NP:** Instamojo account + KYC (sole-prop, PAN+bank); ₹3,000 product; upload `.md`+`HOW-TO.md`;
  paste description + policies; set the **deep-link success redirect** + webhook + salt; test payment.
- **Claude:** all code (Worker + app deep-link handler + redeem/poll + fallbacks), all copy
  (`concall-decoder.md`, `HOW-TO.md`, policies, website pages), exact URLs/salt instructions.
